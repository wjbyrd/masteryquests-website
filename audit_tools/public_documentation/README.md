# Public documentation checks

The inventory in `pages.json` covers public information pages, including the two generated references. Gameplay, interactive hubs, private classroom builds, the converter tool, and historical examples are separate surfaces.

From the repository root:

```text
node audit_tools/public_documentation/check.cjs
python audit_tools/public_documentation/check-downloads.py
node audit_tools/faculty_lo/validate-guide.cjs
node audit_tools/telemetry_data_dictionary/check.mjs
node audit_tools/telemetry_data_dictionary/render.mjs --check
```

The first command checks internal page/asset/anchor destinations, public terminology, Composer workflow order against the actual UI, and required collection/privacy framing. Missing-file and missing-anchor negative controls must fail. The download check uses only Python's standard library.

Outcome guide labels and content remain generated by `audit_tools/faculty_lo/build-guide.cjs`; edit its template for introductory copy, and its canonical outcome source for labels. This refresh regenerated only the guide's inherited footer. The telemetry dictionary's field region is generated from `fields.json`; its surrounding introduction is authored directly in the page. Do not hand-edit generated field rows.

The four teaching DOCX guides are retained authoring artifacts: no tracked generator was found. Preserve their design, make targeted corrections, and render all pages before replacing downloads. Word was used for this audit because the packaged LibreOffice renderer was unavailable on Windows. Other authoring references, the validator workbook, question/resource content, and runtime files were left unchanged.

The pre-edit audit matrix, link results, regression logs, browser QA and final scope proof are retained in `validation_artifacts/public_documentation_refresh/`. The full Composer suite remains a separate regression command; no existing runner is changed by these checks.
