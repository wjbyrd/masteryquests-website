Recommended workflow

Use the shortest path that fits your goal

  1. 01

    Choose your faculty goal

    Use the Build a Quest checkboxes to reveal the composer, manual resources, deployment guidance, validator, converter, or examples.

  2. 02

    Build with the composer or manual template

    For economics, select concepts, assign checkpoint stages, choose modes, and generate. For another subject, author and validate the required pools.

  3. 03

    Test the downloaded package

    Keep the HTML and question-assets folder together. Launch every enabled mode, miss questions intentionally, and inspect repair, bridge, bosses, saving, CSV, and mastery reporting.

  4. 04

    Publish the complete folder

    Upload the folder to GitHub Pages or another static host. Do not upload only the HTML when the generated package contains question assets.

  5. 05

    Deploy and verify in Canvas

    Use the public URL as a course link or embed it according to institutional settings, then test it in Student View before assigning it.

Canvas deployment

From generated ZIP to a student-ready activity

The game is a static website. Canvas provides the course doorway; the hosted folder provides the actual game.

01

Extract and preserve the folder

Keep the generated HTML, recipe, manifest, README, and question-assets in their original relative locations.

02

Host and test the public URL

Open the hosted game in a private browser window and verify images, modes, local saving, downloads, and mobile layout.

03

Add it to Canvas

Create a page, module link, or approved iframe embed. Use Student View and confirm the activity opens without mixed-content or path errors.
