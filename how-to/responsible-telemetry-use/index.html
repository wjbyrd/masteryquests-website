Faculty Resources

Responsible Telemetry Use

Use game records to ask better instructional questions. Students can inspect their own supported Download Game Data CSV, including the general behavioral record available when that file is submitted. Explain the purpose and context of review before asking for a file.

Read interactions in context

  • activeResponseTimeMs is visible-document time, not verified attention. hiddenTimeMs is hidden-document time. unfocusedTimeMs may overlap hidden time; do not add them together.
  • tabSwitchCount records visibility transitions, not the destination or activity in another tab.
  • copyCount records a relevant copy action, not copied content. Selection behavior does not identify its purpose.
  • Rapid guessing is an assessment/behavioral signal, not proof of misconduct. An incomplete run can reflect interruption or data loss.

Do not create automated cheating scores, make single-field accusations, or infer intent without supporting evidence. Consider mode, response history, assistance, missing data and the student’s explanation. These measurements alone do not establish cognition or learning.

Appropriate uses include assessment QA, examining participation patterns, distinguishing elapsed from visible response time, studying remediation, and research under appropriate institutional procedures. For exact definitions, use the Telemetry Data Dictionary.

Know which build and copy you have

Public Managerial/default Composer telemetry is local-only. Private classroom/research builds may transmit anonymous records when enabled. The private control stops future transmission and cancels pending events; it does not delete accepted server records. See collection and opt-out boundaries.

A downloaded local CSV stays on the student/faculty device unless deliberately shared. Submission through Canvas or another system transfers custody to that recipient/system. An admin export creates another copy outside the telemetry database. Server deletion cannot remove arbitrary downloads, submitted copies or backups.

Handle files deliberately

  • Use the institution-approved storage and submission location; limit access to the people authorized for the stated purpose.
  • Avoid public links and unnecessary copies. Treat a browser/run identifier as linkable even when it is not a name.
  • Record where exports are held, who received them and the approved disposal decision. Dispose of each copy through the receiving system’s process; do not assume a server purge reaches it.
  • Ask the owner/institution to decide retention, access and disposal. This guide does not supply an institutional retention period or compliance approval.
