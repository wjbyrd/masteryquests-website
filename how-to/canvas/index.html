LMS deployment

Add your game to your course.

Composer-generated games are self-contained HTML files. Publish the game at a public HTTPS URL, then point your LMS directly at that URL. You can embed the published game directly in a course page.

Publish the GameCopy the Iframe Pattern

Step 1

Publish the generated HTML with GitHub Pages

GitHub Pages is a convenient static host. Another HTTPS static host works too. Follow the illustrated publishing guide for the full hosting steps.

  1. 01

    Extract the Composer ZIP

    Keep the recipe, manifest, README, and publish.html helper for your records. The game has a unique filename beginning game-mqb-.

  2. 02

    Keep the generated filenames

    Upload the supplied index.html launcher and its game-mqb-….html file together. The unique game file contains the JavaScript, CSS, questions, artwork, and graphs for that build. Do not rename it.

  3. 03

    Create or open the GitHub repository

    Upload both files to the Pages publishing folder and commit them. To keep several games, use separate folders such as game-one and game-two. Keep earlier game files while course assignments still link to them.

  4. 04

    Turn on GitHub Pages

    In the repository, open Settings → Pages, choose Deploy from a branch, select the main branch and the root folder, then save.

  5. 05

    Verify the downloaded build

    Wait for the Pages deployment to finish. In the Composer’s Generate step, or the package’s publish.html, enter the public folder URL, for example https://wjbyrd.github.io/test/. Open the generated versioned game link and check Game build information against the manifest. Test the enabled modes, questions, graphs, mobile layout, saving, and results.

Step 2

Copy the completed Canvas embed

Choose Copy Canvas embed HTML in Generate or in the downloaded publish.html. Paste it into the Canvas page’s HTML editor, save, and preview as a student. The helper inserts the actual build automatically and preserves existing URL parameters. The pattern below is illustrative; use your generated code.

<iframe
  title="Mastery Quest game"
  src="https://wjbyrd.github.io/test/game-mqb-YOUR-BUILD-ID.html?v=mqb-YOUR-BUILD-ID"
  width="100%"
  height="900"
  style="border:0;"
  loading="lazy"
  allowfullscreen>
</iframe>
01

Use the versioned game link

The game URL opens your exact build. The Canvas embed field contains the full iframe HTML. Copy that field when embedding; use the game URL for an external course link.

02

Adjust the height if needed

900 pixels is a practical starting point. Increase it if your LMS theme creates unnecessary internal scrolling.

03

Preview as a student

Test desktop and mobile. If your institution blocks the iframe, use the same versioned HTTPS game URL as an external LMS link.

Update a game or publish a different one

Update this game: import its saved composition recipe, edit, generate, and upload the new package’s game file and launcher. The Game ID stays the same; the Build ID changes. Verify the new versioned link, then replace the iframe HTML in Canvas. The Composer cannot update a Canvas course for you.

Publish another game: choose Start a different game in Game details (or Clear Composition). This creates a new Game ID even if you keep the same title or settings. Use https://wjbyrd.github.io/test/game-one/ and https://wjbyrd.github.io/test/game-two/ for separate assignments. Keep their earlier game files available. An old build link continues opening that exact file; deleting it produces a broken link.

Saved progress: regeneration and presentation changes retain compatible saves. Changed questions, graphs or checkpoint routes use separate save slots and leave the old saves intact. Students can resume the old session through its retained original game file. Legacy recipes have no reliable Game ID and receive a new one when imported; keep the original game to access its legacy saves.

If an older game still appears

  1. Open the newest package’s publish.html, enter the correct public folder, and copy its versioned game URL.
  2. Check that the uniquely named game file was uploaded to that exact folder and the Pages deployment finished. A successful deployment does not prove the iframe points to the file you replaced.
  3. Compare Game build information with the newest manifest, then replace the Canvas iframe code and reload the course page.

An unchanged iframe URL or cached index.html can still show an older build. GitHub Pages response caching cannot be fixed with HTML meta tags. The generated embed avoids that cached entry by requesting a new game filename. Do not clear student browser storage to fix a publishing problem. Previously opened tabs continue their current build until navigated to the new link.

Before you assign it

Run the final checks before students do.

Mode check

Launch every mode you enabled. Timed Trial should run for the full ten-minute clock; Exam Drill lets students review and revise a nine-question section before committing it at a checkpoint; correctness stays hidden while that section is active.

Storage check

Progress and run data stay in the learner's browser. Test save/resume only in modes that support it and confirm clearing browser data behaves as expected.

Evidence check

If students must submit a result screenshot, mastery report, verification code, CSV, or other course evidence, state that requirement explicitly in your LMS. Use Mastery Report guidance to interpret supported reports and Class Answer Analysis to examine supported question-response CSVs. See Understanding Game Data: export formats to identify the Composer CSV format.
