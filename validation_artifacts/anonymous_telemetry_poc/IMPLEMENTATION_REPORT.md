5. **Backend architecture:** standalone Cloudflare Worker in `server/anonymous-telemetry-poc/`. It is intentionally separate from the root static Cloudflare Assets configuration, which remains unchanged.
6. **Storage architecture:** Cloudflare D1 with normalized `telemetry_events` and `telemetry_runs` tables, ingest-batch duplicate accounting, client-minute rate windows, indexes, and migration `0001_initial.sql`. Only selection reason, a bounded weakness estimate, and the source event may occupy `extras_json`.
7. **Telemetry schema:** version `1`; build `managerial-directorate-telemetry-poc`; build version `2026.09.04-poc1`; exact phase `phaseAnonymousTelemetryPOC-v1`.
8. **Meaningful events:** `mode_selected`, `run_started`, `run_paused`, `run_resumed`, `question_shown`, `answer_submitted`, `answer_evaluated`, `feedback_shown`, `room_advanced`, `rapid_guess_detected`, `repair_triggered`, `repair_question_shown`, `repair_question_answered`, `bridge_triggered`, `bridge_question_shown`, `bridge_question_answered`, `retest_triggered`, `retest_question_shown`, `retest_question_answered`, `adaptive_detour_ended`, `checkpoint_started`, `boss_question_shown`, `boss_question_answered`, `checkpoint_completed`, `graph_question_shown`, `graph_question_answered`, `score_changed` in score-bearing modes, `streak_changed`, `artifact_unlocked`, `run_completed`, and `mastery_report_summary_emitted`. `run_abandoned` is deliberately omitted because page closure does not prove abandonment. A distinct `artifact_used` event is omitted because the audited build unlocks rewards but exposes no separate power-up-use action.
9. **Anonymous identifiers:** `anonymousClientId` is a cryptographically random UUID persisted in private namespaced local storage. Each new game run receives a new random UUID `runId`; saved-run/source-run mapping preserves it on resume. IDs are not derived from time, IP, user agent, screen, hardware, email, or any user value. Per-run sequence counters persist and increase monotonically.
10. **Retry/buffering:** a 2,000-event capped local queue preserves creation order, survives refresh, sends batches of 25, acknowledges by event ID, retries with capped exponential backoff, retries on `online`, and attempts keepalive flushes when hidden/unloaded. All capture/transport paths are fail-open.
11. **Duplicate protection:** every event has a client UUID; D1 has `event_id` primary-key and `(run_id, sequence_number)` uniqueness; ingestion pre-detects known IDs and uses `INSERT OR IGNORE`; duplicate batches are acknowledged without incrementing run aggregates.
12. **Explicitly not collected:** name, username, email/school email, student/SIS/Canvas/LMS/account ID, IP in application payloads, precise location, user agent, screen/device/hardware fingerprint, ad ID, credentials, free-response text, or arbitrary extras. The server rejects forbidden identifier keys and unknown research fields.
13. **Developer controls:** append `?telemetryDebug=1` for a collapsed diagnostic panel showing client/run IDs, next sequence, queued count/recent queue, endpoint, phase/build/schema, synthetic status, failed sends, last success, last response, and last status. Controls create a fresh run ID while preserving the client, reset the client ID, flush, simulate failure, and verify resume mapping. Add `&telemetrySynthetic=1` to mark manual QA events synthetic.
14. **Protected server QA:** bearer-authenticated endpoints provide totals/recent runs, one-run ordered events, deterministic reconstruction, anomaly reporting (duplicates, gaps, out-of-order arrivals, incomplete runs), and CSV export. A local JSON reconstruction CLI is included.
15. **Cleanup:** bearer-authenticated `POST /v1/admin/cleanup` with `scope: synthetic` deletes synthetic events/runs/batches; `scope: build` plus the POC build ID deletes the entire build dataset. Both require `confirm: DELETE`. Commands and routes are documented in the backend README.
16. **QA scenarios:** synthetic A–K cover normal completion, rapid guessing, high misses with repair/bridge/retest, checkpoints, refresh/resume, close/return, failure/recovery, duplicate retry, multiple runs on one client, client reset, and every supported mode.
