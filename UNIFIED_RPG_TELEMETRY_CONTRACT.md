# Unified RPG CSV contract

Version: **mq-rpg-csv/1**. Canonical count: **137**. The authoritative ordered field registry is [schema.json](audit_tools/unified_rpg_telemetry/schema.json). Its columns array is the only maintained header; generated HTML copies are checked against it. The [audit](UNIFIED_RPG_TELEMETRY_AUDIT.md) and [machine-readable crosswalk](audit_tools/unified_rpg_telemetry/baseline.json) were completed before product changes.

## Design decisions

Keep the historical 117 names/order first, then 16 Risk & Reward fields and gameplayResponseTimeMs (the union of 70/88/117), then three export metadata fields. No useful field is retired; no duplicate alias column is introduced. The two response clocks are distinct measurements, not duplicate aliases. Preserve mq-measurement/1 and original tracker revisions for manifest/private compatibility. csvSchemaVersion versions this new local export boundary independently. The private admin envelope and Worker configuration are unchanged.

New observations retain a typed normalization snapshot beside the existing local row. The existing row remains available to gameplay, mastery calculations, private transport, and historical tests. Export copies the snapshot, applies disclosure rules, and serializes one CSV. No new randomness, timers, listeners, question attempts, scoring operations, or progression operations are introduced. Newly preserved measurements are existing emitted payloads that the older serializer dropped: especially Risk & Reward in Composer/Economic/Macro and Exam/checkpoint/artifact payloads absent from narrower headers. This is not new behavioral surveillance.

## Availability and types

A real measured zero remains 0. An applicable boolean remains 0/1. Unavailable numeric/boolean values serialize as blank cells. fieldAvailabilityJSON names each blank field's reason: not-applicable (wrong mechanic/event/mode), not-measured (applicable but no source observation), unavailable (invalid/interrupted or withheld at an assessment disclosure boundary), or legacy-ambiguous (an older default cannot reliably be distinguished from an observation). It contains field names and reason codes only. No clipboard contents, names or added learner identifiers are collected.

Scope and sources are specified per field in schema.json. An explicit non-null event payload is an observation; absent data is not converted through Number(null). Nonfinite numbers are unavailable. Metadata and genuinely measured existing tracker/snapshot values are copied. Lifecycle rows do not become wrong answers or zero-duration responses. Draft correctness and answer keys remain withheld. Raw fields are not retroactively rewritten on save/resume. Legacy rows retain their original tracker identity; ambiguous defaults are blanked only in the versioned export with an explicit reason.

## Timing and events

All duration units are milliseconds; timestamp and dailyCompletionTimestamp retain their original UTC ISO representation. DailyDate remains the local calendar date chosen by the Daily engine. All active producers inspected already use milliseconds. No factor-of-1000 conversion is applied. responseTimeMs is the recorded response interval; activeResponseTimeMs is only the observed visible portion. Labyrinth has no visibility decomposition. gameplayResponseTimeMs preserves Managerial's separately measured original clock. No exporter estimates visible time from wall time or fills a missing interval with zero.

Only question rows are accepted answers. Rapid guesses and Exam drafts remain separate. Revisions, retries and presentation IDs keep their original identities and sequence. Completion comes from explicit terminal events, not CSV download. Guardian outcome names remain game-specific; use recorded checkpoint outcomes where supplied, never translate boss_defeated into three correct answers automatically. Daily Tasks and artifact inventories retain their underlying game's applicability. Scores and question pools remain different across games.

## Privacy and legacy imports

Existing download deferral remains in force. During active Exam exports, correctness, revision-direction outcomes, streak/score indicators, checkpoint results and target labels, Daily Task progress, and snapshot answer keys are withheld, including earlier committed rows. Stored unfinished reports retain this protection after reload or switching runs. A recorded complete, exam_complete or exam_ended_by_student event authorizes accepted results; Daily completion is not Exam completion. Completed reports retain authorized accepted answer snapshots. Drafts never gain a correct-option key. Importers identify the new schema by version and header names; unknown future versions stop interpretation. Validators retain the exact legacy 70/88/117 schemas plus earlier documented formats and the separate private envelope. Historical exports are interpreted under their original definitions; missing fields are not reconstructed from today's question bank.

## Generator and validation obligations

Shared runtime owns normalization; the existing contract generator embeds it, the existing Composer/realm/Macro generators propagate it, and Managerial's maintained adapter installs the same columns. Micro and manual-template measurement sync uses the same helper. Synchronization must be idempotent and source-protection checks must exclude only measurement changes. Tests must assert values, actual downloaded headers, blank reasons, legacy imports, mode coverage, privacy, persistence, random-call equality, gameplay regressions and publication output. Synthetic CSVs/screenshots/logs live in ignored tmp/unified-rpg-telemetry.
